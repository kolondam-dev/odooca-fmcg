# Tahap 3A — kedalaman bisnis penjualan dan margin buku

Basis: main e4aa776 (merge PR71). Tahap 3A menambah analisis yang sumbernya sudah tersedia; seluruh tahap 3 belum dinyatakan selesai. Tidak mengubah workflow PWA, seed/register, atau data server.

| Metrik | Kontrak yang diimplementasikan |
| --- | --- |
| SO bersih, diskon, tren | Confirmed SO; subtotal DPP dikonversi ke currency company pada tanggal SO dalam WITA. Nilai baris signed termasuk penyesuaian negatif; count SKU/LPO hanya kuantitas positif. Fulfillment memakai positive ordered value sebagai denominator agar credit/adjustment tidak menggelembungkan rasio. Tren memakai populasi baris SO yang sama. Semua company terpilih harus satu currency. Valuta asing memerlukan kurs eksplisit untuk currency asal dan company; tidak memakai fallback 1 sebagai fakta bisnis. Cache faktor per company/currency/tanggal pada satu query. |
| Target SO segmen | Konfigurasi independen per company, rentang tanggal, dan salesperson/channel/area/principal. Target bersifat SO bersih, berbeda dari target invoice finance. Empat dimensi tidak dijumlahkan. Hanya exact period dibandingkan; filter tambahan yang memotong segmen menghasilkan capaian unavailable, bukan perbandingan parsial terhadap budget penuh. Target positif, satu dimensi, periode tidak overlap; update tanpa perubahan nilai pada company menjadi guard konflik transaksi config (bukan perubahan nilai master). |
| Hak target | Salesperson hanya membaca target salesperson miliknya; manager membaca/menulis target pada company yang diizinkan. Global company rule berlaku pula untuk direct RPC model. Configuration merupakan versi aktif saat query; belum merupakan budget historis immutable. |
| Assortment | Universe seluruh produk aktif saleable yang dapat dibaca, termasuk principal/brand tanpa penjualan. Persentase = distinct sold SKU yang masih dalam universe / eligible SKU. Sold SKU di luar universe dilaporkan terpisah, tidak menaikkan persentase di atas100%. Universe adalah master saat query, bukan snapshot katalog historis atau assortment eligible per outlet. |
| Aktivitas outlet | Distinct company+partner SO pada periode kini/pembanding; retained/entered/exited berasal dari set intersection/difference. Entered bukan first-ever customer, exited bukan permanent churn. Tidak menyebut nilai SO nol sebagai pembayaran/omset akuntansi. |
| PJP resmi | Planned slot = company+user+hari WITA+outlet exact. Numerator memakai command `sales.visit.check_in` accepted sesuai assignment; anchor waktu adalah server create_date. Multiple check-in dalam slot yang sama dihitung satu. Assignment yang diarsipkan tetap dibaca pada pelaporan historis. |
| Bukti PJP | Evidence metadata harus cocok assignment/user/company/warehouse/outlet/hari; cakupan bukti ditampilkan terpisah. Foto berdiri sendiri bukan kunjungan. Read-model mempercayai record evidence resmi; tidak membaca/memvalidasi ulang binary atau menggantikan validasi endpoint. Historical photo seed tidak dimigrasikan menjadi check-in fiktif. |
| Effective call | Satu slot check-in accepted yang diikuti confirmed SO dengan date_order >= server check-in, pada company/user/outlet/hari WITA yang sama. Tidak menyamakan outlet saudara yang commercial parent-nya sama. Ini attribution temporal terdefinisi, bukan bukti sebab-akibat atau waktu device offline. |
| Scope/coverage PJP | Native ACL/rules tanpa sudo. Non-system scope own; system dapat melihat plan/command pada company terpilih. Command tak terbaca menghasilkan unavailable, bukan0%. Scope dan bukti invalid/out-of-assignment diekspos sebagai metadata quality. Query besar ditolak agar tidak menghasilkan agregat parsial diam-diam. |
| Margin bruto buku | Untuk account user/system: posted AML berdasarkan accounting date pada periode dan company yang punya target finance terpilih. Revenue=-SUM(balance) akun operating income; direct cost=SUM(balance) akun expense_direct_cost; margin=revenue-cost. Refund/adjustment signed ikut, draft/outside-period tidak. Tidak sama dengan margin per SO/per invoice, invoice-date DPP, atau net margin. Income/cost coverage yang tidak ada menghasilkan unavailable, bukan margin100%. Invoice-only role tidak menerima nilai biaya/domain. Jurnal sumber dapat dibuka. |

## Regresi dan visual

Tes native mencakup nol penjualan, outside-catalog, target empat dimensi dan filter parsial, ACL/company target, overlap, kurs hilang/valid, outlet period set, foto tanpa check-in, SO sebelum/sesudah, sibling outlet, duplicate slot, archived assignment, signed ledger/refund/draft/date, dan cost role denial. Fixture visual ci_db memakai target SO, principal tanpa penjualan dan jurnal biaya langsung sintetis; angka margin diperiksa terhadap ledger sebelum screenshot. Screenshot bukan acceptance staging/perangkat.

## Sisa tahap 3 dan kesiapan aset

Implementasi read-model berikutnya dijelaskan di [STAGE3B.md](STAGE3B.md), dengan batas rekonstruksi dan coverage yang eksplisit. Backlog lanjutan: audit historis immutable, promise-to-pay, bridge invoice/delivery dan actual margin per-order dengan mapping COGS, backlog/OTIF/H+1/H+2 dengan cohort/calendar/cutoff yang eksplisit, reasons per line/DO, distribusi assortment eligible per outlet dan weighted distribution. Tidak membuat metrik kosong dengan angka perkiraan untuk menyatakan semuanya selesai.
